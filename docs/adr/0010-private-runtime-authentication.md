# ADR-0010: Per-runtime credentials: HMAC forwarding secret, admin token, service token

Status: Accepted

## Context

ATLAS must call each runtime (forward events, push configuration, check
health) and each runtime must call ATLAS (MCP broker, usage). Neither
direction may rely on dashboard cookies or on shared platform-wide secrets.
The runtime already authenticates Slack-shaped requests with an HMAC secret
and admin requests with a bearer token.

## Decision

Three credentials per runtime, all generated by ATLAS at provisioning,
unique per runtime, stored per ADR-0007, and rotatable independently:

| Credential | Direction | Delivered to runtime as | Used for |
| --- | --- | --- | --- |
| Forwarding secret (32 random bytes) | ATLAS -> runtime | `MOM_SLACK_SIGNING_SECRET` | Signing forwarded Slack events with the `v0` scheme (ADR-0002) |
| Admin token (32 random bytes, base64url) | ATLAS -> runtime | `JARVIS_ADMIN_TOKEN` | Projection pushes through `/api/admin/*`, supervised restart |
| Runtime service token (32 random bytes, base64url, prefix `atlr_`) | runtime -> ATLAS | `ATLAS_RUNTIME_TOKEN` and the credential of each projected `mcp-http` connector | `/mcp/v1/*`, `/internal/runtimes/:id/*`; ATLAS stores SHA-256 only |

Rules:

- Network layer: runtimes have no public ingress; ATLAS reaches them over
  the provider's private network (ADR-0009). Credentials are still required
  on every request; network position is not identity.
- Identity binding: the token hash resolves `(tenant_id, runtime_id)`. Any
  path `:id`, header, or body identity that disagrees is rejected with 404
  and audited as `runtime.identity_mismatch`.
- Rotation: create the new credential, push it (variables update and
  redeploy for the two inbound ones, projection push for the service token),
  keep the old service token valid for a 15 minute grace window, then revoke.
  Exposed through `POST /api/operator/tenants/:tenantId/runtime/rotate-credentials`.
- Suspension revokes service tokens immediately, so a stopped runtime that
  is restarted out of band cannot call ATLAS.
- Health checks (`GET /health`) are unauthenticated on the runtime side; that
  endpoint returns no data beyond `ok`.

## Consequences

- No Jarvis code change is required for either inbound credential.
- ATLAS holds the admin token and forwarding secret in plaintext-recoverable
  form (encrypted at rest); compromise of ATLAS's key ring compromises all
  runtimes' inbound control, which is inherent to a control plane and is
  addressed by key rotation and operator controls.

## Alternatives rejected

- Mutual TLS between ATLAS and runtimes: no certificate infrastructure for
  the pilot; revisit with a service mesh or provider mTLS.
- A single platform-wide runtime secret: a compromised runtime could
  impersonate any runtime.
- Short-lived JWTs issued by ATLAS to runtimes: adds clock and key
  distribution complexity without changing the trust model.
